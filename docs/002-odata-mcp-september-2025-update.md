# sap-odata-mcp-universal: ключевые изменения и текущее позиционирование

**Документ:** 002  
**Дата:** 2026-04-23  
**Статус:** актуально

---

## Зачем обновлялся проект

Проект больше не описывается как просто "Go port" старого bridge. Текущее состояние продукта другое:

- единый MCP-сервер для SAP OData
- HTTP dashboard для управления несколькими SAP-системами
- переключение активной системы без рестарта процесса
- двуязычный интерфейс и встроенная документация
- единое имя проекта: `sap-odata-mcp-universal`

Именно вокруг этого сценария теперь строится основная эксплуатационная документация.

---

## Что изменилось в продукте

### 1. Dashboard-first сценарий

В HTTP-режиме сервер теперь может стартовать без начального `--service`.

Это позволяет:

- поднять один процесс
- открыть `/dashboard`
- сохранить несколько SAP OData подключений
- выбрать активную систему
- подключить MCP-клиент к одному `/mcp`

### 2. Персистентный реестр подключений

Dashboard хранит:

- список SAP OData профилей
- активное подключение
- режим доступа для профиля
- логин/пароль для автопереподключения после рестарта

Файл состояния можно переопределить через `ODATA_MCP_STATE_FILE`.

### 3. Два эксплуатационных режима

`stdio`:

- один бинарь
- одна SAP-система
- удобно для Claude Desktop и простого локального использования

`streamable-http`:

- один сервер
- несколько SAP-систем
- dashboard
- единый `/mcp` endpoint для MCP-клиентов

### 4. Универсальный инструмент

Флаг `--universal` остаётся важным для больших сервисов.

Он нужен, когда:

- entity sets слишком много
- MCP-клиент получает слишком большой набор tools
- нужно уменьшить токеновую нагрузку

### 5. Безопасность HTTP-транспорта

Текущий security contract:

- для любого HTTP-режима обязателен `--mcp-token`
- для non-localhost bind обязателен `--tls`
- для `0.0.0.0` и `::` дополнительно обязателен `--allow-all-interfaces`

Это поведение намеренно жёсткое и отражено в новой основной документации.

## Что изменилось в документации

Документация теперь ориентирована не на marketing/blog-style описание, а на реальную эксплуатацию:

- как поднять сервер
- как использовать dashboard
- как подключить `Codex`, Claude Desktop и HTTP MCP-клиентов
- где лежит state file
- как устроены режимы доступа
- как диагностировать типовые проблемы

---

## Что важно помнить

1. Dashboard не шифрует пароли в state file.
2. Для публичного HTTP-доступа нужен TLS.
3. `streamable-http` является рекомендуемым transport для новых MCP-клиентов.
4. `stdio` остаётся самым простым вариантом для одного конкретного SAP-сервиса.
